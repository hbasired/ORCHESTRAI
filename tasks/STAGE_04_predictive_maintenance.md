# Stage 04 — Predictive Maintenance (the PREDICT step of the self-healing engine)

> First ML stage and **step (1)** of the Causal Self-Healing Cognitive Engine (KB_25): a learned model that
> forecasts asset failure (machine_crack / robot_down) *before* it fires, so the coordinator can diagnose →
> verify → intervene rather than only react. Per CTO Checkpoint #1, this begins the **one vertical slice**
> (predict→diagnose→intervene) the project should finish before widening further. Free-cost (CLAUDE.md rule 9):
> train on Colab-free / local; Groq only for any LLM glue.

## Acceptance criteria

- [ ] A failure-prediction model exists under `backend/ml/` (and training under
      `backend/training/stage_04_predictive_maintenance/`) — an **LSTM-Autoencoder + Transformer-encoder** (or a
      CNN-LSTM/Transformer-GRU hybrid; pick per eval) that, given a rolling window of SimPy plant telemetry,
      outputs `P(failure within horizon H)` per machine/robot with a confidence.
- [ ] Trained on a **free, license-clean dataset** — either (a) telemetry generated by the Stage-2 SimWorld
      (preferred: self-consistent), or (b) a public PdM dataset (e.g. AI4I 2020 / NASA C-MAPSS — record the
      license in KB_03). DVC-tracked.
- [ ] `models/pdm_failure_predictor.*` ships with `models/pdm_failure_predictor.metrics.json` +
      `compliance/model-cards/pdm_failure_predictor.md` (CI gate `check-model-cards.sh`).
- [ ] Eval against a stated baseline (naive "always healthy" + a simple threshold) — report ROC-AUC / PR-AUC +
      lead-time (how early it predicts) in `backend/training/.../results.json` (KB_23 contract). No metric without a baseline.
- [ ] A `predict_failure(window) -> {target_id, p_fail, horizon, confidence}` inference entry point the
      coordinator can call (sync, CPU, < 50 ms) — the seam for engine step (2) diagnosis.
- [ ] **No theatrical fallback** in the inference path (no `random.*`); if the model file is absent, raise / return
      a typed "model-unavailable" error, not fabricated probabilities. Audit count strictly decreases (< 411) by
      replacing the stubbed predictor in `backend/ml/`.
- [ ] (groundwork, optional this stage) emit predictions as an observable agent-trigger event (G-021) so the
      future PdM dashboard (G-006) and live observability can consume them.
