## Gaps (fix before final polish — neither is a FAIL)

### Gap 1 (LOW–MEDIUM, CI hygiene): `datamodel-code-generator` is NOT in `requirements.txt`
The task doc ("Files to MODIFY → requirements.txt: add `datamodel-code-generator`"), the ADR
(D-consequences: "`requirements.txt` (datamodel-code-generator)"), and KB_TASK_LOG all claim it was added — but
`grep -ni datamodel backend/requirements.txt` returns **nothing** (only `paho-mqtt==2.1.0` near it). The CI
`vda5050-schema-validate` job does only `pip install -r requirements.txt` then runs
`bash integrations/vda5050/compile_models.sh` → `python -m datamodel_code_generator`. In a clean CI runner that
**regenerate step fails with ModuleNotFoundError** (the package is standalone — nothing pulls it transitively).
It passes locally only because the implementer has 0.64.1 installed in their env. This is a documentation/code
mismatch (an over-claim that the dep was added) + a latent CI break. **Fix:** add
`datamodel-code-generator` (as a dev/build dep) to `requirements.txt`. (`jsonschema` is also not declared but
arrives transitively via the pinned `mcp>=4.20.0`/chromadb/dice_ml/ray, so the schema test itself is safe — minor
hygiene only; declaring it directly would be cleaner since the test imports it directly.)

### Gap 2 (LOW, dangling reference): `G-075` cited in test code but absent from the ledger
`test_stage16_remediations.py:149,152` and the docstring reference **G-075** (the Ollama-image-not-pullable skip
reason). `grep -ni G-075 audits/OPEN_GAPS_LEDGER.md` returns nothing — there is no G-075 row. On THIS box Ollama
is up and the test RAN, so the skip path is dead, but the dangling ledger ID is sloppy. **Fix:** either add a
G-075 ledger row (env-dependent Ollama availability) or remove the G-075 reference from the test comments.
