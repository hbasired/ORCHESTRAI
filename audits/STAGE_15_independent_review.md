## Per-criterion evidence

### 1. Real Sparkplug B protobuf — NOT a hand-faked dict. PASS (strongest finding)

`backend/integrations/sparkplug/sparkplug_b.proto` is the **canonical Eclipse Tahu v3.0** definition
(`package org.eclipse.tahu.protobuf`, the full Payload/Metric/DataSet/Template/PropertySet message tree).
`sparkplug_b_pb2.py:1-3` is genuine `# Generated by the protocol buffer compiler. DO NOT EDIT!` code with the real
`AddSerializedFile(...)` descriptor (`sparkplug_b_pb2.py:17`). I **re-compiled the proto with `grpc_tools.protoc`
and diffed the output against the committed `_pb2` — they are identical** (modulo the protoc version comment). This
is dispositive that the wire format is a real protobuf, not a dict literal masquerading as Sparkplug. `payload.py`
sets the **correct typed `value` oneof per datatype** (`add_metric`, lines 75-90), encode/decode use
`SerializeToString`/`ParseFromString` (lines 107-114). Datatype roundtrip test asserts exact values back out.

### 2. Sparkplug lifecycle is real (research §25.1). PASS

`client.py` (paho-mqtt 2.x, CallbackAPIVersion.VERSION2):
- **NDEATH as the MQTT Last-Will** registered at CONNECT carrying `bdSeq` (`connect()`, lines 75-89,
  `self._client.will_set(...)`).
- **NBIRTH right after CONNECT** — `seq=0`, same `bdSeq`, a `Node Control/Rebirth` metric + node metrics
  (`_on_connect` → `_publish_nbirth`, lines 91-108).
- **seq 0–255 wrap** — `_next_seq` (lines 53-58) returns then `(s+1)%256`; unit test
  `test_seq_wraps_0_to_255` asserts `[254,255,0,1]`.
- **bdSeq** per session (`connect` increments mod 2^64; stable within a session — the live test asserts
  `node.bd_seq == first_bdseq` after disconnect).
- **NCMD `Node Control/Rebirth=true` → re-NBIRTH** (`_on_message`, lines 140-143).

The live `test_full_lifecycle_over_real_broker` runs the whole sequence over **real Mosquitto** with an independent
subscriber capturing NBIRTH(seq0, bdSeq, Rebirth, valid MAC) → NDATA(seq1) → NCMD-Rebirth → fresh NBIRTH(seq0) →
NDEATH. It **passed live (not skipped)** this session.

### 3. OPC UA roundtrip is real asyncua over TCP. PASS

`opcua/server.py` builds a real ISA-95 Part-2 tree (Enterprise→Site→Area→WorkCenter→WorkUnits with
Status/OEE/Temperature/UnitsProduced vars) on an actual `asyncua.Server`. `opcua/client.py` is a real
`asyncua.Client` that `connect()`s, browses, reads, and subscribes. `test_opcua_roundtrip.py` binds a loopback TCP
endpoint (`opc.tcp://127.0.0.1:48401/...`), browses the tree, reads a value back, and receives a **live
data-change subscription notification** — **passed live**. asyncua 1.1.5 confirmed installed. No stub/mock anywhere
in the path.

### 4. HMAC-SHA-384 integrity is real (Rule 2 / KB_13). PASS

`payload.py:119-147` MACs over the canonical payload with the MAC metric **cleared** (`_strip_mac`), attaches the
48-byte tag as the `MAC/HMAC-SHA384` Bytes metric, and `verify_payload_mac` re-derives + constant-time-compares via
`crypto/hmac_sha384.py` (`hmac.compare_digest`, SHA-384). My adversarial probes confirmed: **tamper → False,
wrong-key → False, no-MAC-present → False (not a silent True), append-after-MAC (extension) → False, valid → True**;
tag length 48 bytes. No bypass found in the strip/verify round-trip.

### 5. Safety boundary honest (KB_17) — the "actuator" audit hit is a genuine false positive. PASS

- **OPC UA client is subscribe-only**: `opcua/client.py` exposes `read`, `browse_variables`, `subscribe` and has
  **no `write_value`/`set_value`/`call_method`** (grep over the file returns only the disclaimer in the docstring,
  line 5). No write path to external servers.
- The one `node.write_value(value)` in the package is `opcua/server.py:83` `set_telemetry` — this writes the
  **server's OWN local telemetry variables** (so subscribers see a data change). It is not a command to any external
  actuator; it is the server publishing the telemetry it owns. Honest.
- **Sparkplug inbound NCMD/DCMD are parsed-not-executed**: `_on_message` (lines 140-145) acts on **only**
  `Node Control/Rebirth` (a protocol-internal re-sync) and otherwise forwards to an `on_command` callback. No
  actuator/PLC write is issued. The docstring (lines 11-12) states this and the code matches.
- Therefore **no actuator command path was added** this stage; the `safety.validate` gate + write paths are
  correctly deferred to Stage 16/17 (KB_17), as the ADR claims. The "actuator" tokens that appear are confined to
  disclaimers — a true false positive.

### 6. Honest deferrals + capability claims. PASS

  work under 4.25.9; `main.py` imports clean. (TF's *runtime* `import tensorflow` raised `MemoryError` on this box —
