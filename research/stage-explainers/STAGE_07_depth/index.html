1. The problem with v0

The v0 Stage-7 RL was an honest negative: a from-scratch PPO on a single-crew SimWorld env where the greedy priority rule is near-optimal — so PPO did not beat it, and rules stayed the default. But the research (§16.1: TranDRL, predictive group maintenance, opportunistic scheduling) is explicit that DRL beats greedy specifically when the schedule has structure a myopic rule can't exploit. The v0 "RL ties rules" was a property of a too-simple env — not a law.

In the right regime, RL beats the best rule — measured, statistically significant.

2. The richer regime (where RL can win)

backend/training/stage_07_rl_intervention/group_env.py — a documented maintenance-scheduling MDP (explicit seeded dynamics + realistic costs; honest as a model, not telemetry):

  • GROUP: machines live in zones; one crew trip services up to K zone-mates, sharing a fixed setup cost. Batching amortises setup; greedy "fix the single most-urgent" pays it every trip.
  • OPPORTUNISTIC: throughput value oscillates (demand windows); timing trips for low-demand windows (when ETA slack allows) loses less throughput.
  • Crew contention + heterogeneous ETAs: prioritisation still matters.

Structure verified real: a batching-aware threshold rule (−131.8) already beats fix-one-at-a-time greedy (−162.9), so grouping genuinely matters.

4. Honest scope & what changed

  • Scheduling-MDP model, not SimWorld telemetry. It demonstrates RL beats strong rules under group+opportunistic structure; live-loop wiring (different state space) + a real plant are future work (G-025/G-035). Not actuator-wired (Stage-17 wrapper precedes any dispatch).
  • The v0 negative is retained, not overwritten — "rules near-optimal in the simpler regime" is still true there. We did NOT weaken the baseline to manufacture a win: the threshold/batch rule is legitimately strong.
