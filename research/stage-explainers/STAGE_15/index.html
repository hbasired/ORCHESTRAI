1. Why & what

Our agent now speaks the two open standards a real factory already uses, so it can read live equipment telemetry without ripping anything out: OPC UA (the IIoT telemetry standard) and MQTT Sparkplug B v3.0 (the IIoT pub/sub standard). Both feed the Stage-12 ISA-95 equipment graph in Neo4j.

OPC UA server (ISA-95 tree) ──subscribe──> our OPC UA client ──┐ Sparkplug B edge node ──NBIRTH/NDATA (HMAC-SHA-384)──> Mosquitto ─┴─> populate_from_ot_event() ─> Neo4j ISA-95 graph

Telemetry-in + graph population only. No actuator commands — that's the Stage-16/17 safety path.

2. The build (all real, no mocks)

  • OPC UA (opcua/server.py + opcua/client.py, asyncua 1.1.5): an ISA-95 tree (Enterprise→Site→Area→WorkCenter→WorkUnit) with live telemetry vars; a subscribe-only client that browses, reads, and gets data-change notifications. Interim policy Aes256Sha256RsaPss (armed only when certs loaded — reported honestly).
  • Sparkplug B v3.0 (sparkplug/payload.py + sparkplug/client.py): the real protobuf wire format (canonical Eclipse sparkplug_b.proto → sparkplug_b_pb2.py), full lifecycle — NDEATH-as-Last-Will, NBIRTH (seq 0 + bdSeq), NDATA (seq 0–255 wrap), NCMD Rebirth → re-NBIRTH, NDEATH.
  • HMAC-SHA-384 on every payload (quantum-resistant MAC); bad MAC → dropped.
  • ISA-95 population (graph_isa95.populate_from_ot_event): inbound OPC UA + Sparkplug events MERGE Equipment nodes under a WorkCenter (idempotent; honest-unavailable without Neo4j).

4. Honest engineering call (research §25.4)

The Sparkplug B protobuf is compiled by grpcio-tools. Version 1.81 pulls protobuf 6.x, which breaks TensorFlow 2.15 (used by dice-ml in Stage 10, needs protobuf<5). So we pinned grpcio-tools 1.62.3 + protobuf <5.0 — a protoc that emits protobuf-4.x code, TF-safe — and verified the OpenTelemetry OTLP serialize path still works at 4.25.9. Real wire format, no regression.
