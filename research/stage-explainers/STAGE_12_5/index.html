Stage 12.5 — Observability Pipeline CLOSED

Every agent action now emits an OpenTelemetry trace AND an immutable evidence row · ADR 2026-06-15_stage12_5_observability.md · KB_15 · research §21. Verified live (app→OTLP→collector).

1. Why & what

The runtime made decisions (Stage 11) and recorded immutable evidence (Stage 12) — but you couldn't see what it did in real time. Stage 12.5 wires the mutable-trace half of KB_15's two-store split: OpenTelemetry spans → otel-collector → Langfuse (debug, 90-day) + Phoenix (evals), emitted alongside the immutable audit_chain row for the same action.

agent action ─→ OTel span (traced_span) ─OTLP→ collector ─→ Langfuse + Phoenix (mutable, prunable) └─→ audit_chain row (append-only, SHA-256 chained, signed) (immutable, forever)

Two stores by design: lose the trace store and you never lose the evidence.

2. The spans we emit (KB_15 table)

All go through one traced_span(name, **attrs) wrapper, so the experimental OTel GenAI semconv churning upstream is a one-file change. gen_ai.* emit when an LLM runs; safety.validate/ actuator arrive at Stage 17; a2a.* at Stage 14.

3. Honest by construction

otel_init.init() is honest when unconfigured: with no OTEL_EXPORTER_OTLP_ENDPOINT it creates spans (for the in-process record + tests) but does not export them to a fake sink — it returns local-only and says so. No trace is ever claimed to have shipped when it didn't (Rule 1a). The langfuse_sink/phoenix_evals modules report their real active path; the Phoenix eval suites are honestly marked spec-until-Stage-20.
