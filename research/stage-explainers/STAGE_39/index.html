G-045 — decisions that leave a real record

The EU AI Act Article 12 requires high-risk systems to automatically log every algorithmically-driven decision with full input→output provenance. Stage 6 claimed this but only kept an in-memory SliceTrail. Now slice_runner._persist_decision_log() writes each live decision to the Stage-1 decision_logs table:

caller      = "slice_runner"
tool        = <decision kind>                     e.g. preventive_maintenance
input_hash  = SHA-256(telemetry + prediction)     # what the system saw
output_hash = SHA-256(decision + verification)     # what it decided
inputs / outputs = the full JSONB provenance
incident_id = the real UUID FK  (a non-UUID sim tag → inputs.incident_ref instead)

It's wired ON in the live operational path (LiveSliceRunner) and OFF for the offline A/B experiment. Honest by construction: no database reachable → it returns None (surfaced as decision_log_id: null), never a fabricated id.

G-051 — a safety gate that can say "no"

The Stage-6 verify step built a PlantState that relaxed all three rejecting contracts — available_crew = n (unlimited), throughput_floor_frac = 0.0, and max_concurrent_critical_offline = n — so the plan verifier could only ever attach provenance. It now binds:

ConstraintBefore (relaxed)Now (binding)
Maintenance crewn (unlimited)crew_total(2) − stages_in_maintenance (contention)
Throughput floor0.0 (none)0.6 — ≥60% of stages must stay online
Critical redundancyn (unlimited)1 — the SIL cap (never down >1 critical machine)

The verifier engine itself was always genuine (test_plan_verifier.py); the Stage-11 runtime path already bound. Stage 39 brings the Stage-6 slice path to the same honesty — and proves it: the gate now rejects a plan that would breach the throughput floor and one that would down a second critical machine.

The catch that mattered — no false-reject

Making a gate bind risks breaking the normal case. Guarded two ways: a test that the safe single maintenance is still approved, and a full re-run of the Stage-6 A/B — unplanned downtime still drops 190.5 minutes (OFF 470.3 → ON 279.7 min), with 3.67 planned maintenances still firing and getting approved. The binding values are conservative, so the normal single-machine case always passes; only genuinely unsafe plans are rejected.
