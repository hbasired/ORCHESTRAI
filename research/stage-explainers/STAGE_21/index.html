Stage 21 — Disaster Recovery, HA posture & Backups CLOSED

A tested backup→restore→verify DR path + chaos drill for the stateful tier — free/OSS/local, every claim measured live · ADR 2026-06-22_stage21_dr_ha_backups.md · KB_10/KB_15 · research §31.

1. What it built

DR for the stateful tier (Postgres source-of-truth + audit_chain, Neo4j ISA-95 graph, Redis cache) using only free/built-in tools — no paid cloud, no Neo4j Enterprise (Hard Rule 9). The binding deliverable is a tested restore: a backup you've never restored is not a backup.

"Never trust an untested backup" — so the restore drill asserts parity, it doesn't assume it.

3. 3-2-1(-1-0) & honest scope

  • 3-2-1: primary backups/ + a second medium (BACKUP_ROOT_2) + an off-site rclone target that is config-only (not exercised at build time — no paid cloud, Rule 9). SHA-256 manifest = the "0 errors" / immutability anchor.
  • pilot/cloud Multi-node HA & automatic failover (Neo4j Community has no clustering); live off-site replication; continuous WAL archiving is config-provided but OFF by default (enabling a bad archive_command fills the WAL disk → outage). Enable per the docker-compose comment at pilot.
  • G-066 horizontal-scale hardening (multi-worker sharding, PG replicas, load test) is a separate concern from DR → pilot/scale stage. G-060 pgaudit DB-level logging stays a separate ledger item.

4. Honesty notes

  • Two real bugs were caught by running the scripts, not assuming: --no-deps is a compose flag (not docker run) so the first Neo4j backup failed; and MSYS path-conversion rewrote container paths (/tmp, /backups) on Windows. Both fixed (lib.sh MSYS_NO_PATHCONV + docker_host_path) and re-verified.
  • The earlier "pgBackRest @ Stage 14" KB placeholder was superseded — the built-in pg_dump/pg_basebackup path is the honest free choice (pgBackRest is a heavier install; still free OSS if adopted at scale).
