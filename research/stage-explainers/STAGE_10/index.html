1. What this stage built

Stage 10 delivers the "explainable, auditable decisions" trust leg (KB_25): it replaces fabricated random SHAP/attention/counterfactuals with real, exact explanations for the self-healing spine — why a machine is at-risk, and what would make it safe.

Exact TreeSHAP — zero new dependencies — and a counterfactual scored by the actual model.

2. Exact TreeSHAP — the verifiable invariant VERIFIED

The key enabler: XGBoost has built-in exact TreeSHAP via booster.predict(pred_contribs=True) — no shap library needed. backend/ml/failure_explainer.py explains the Stage-4 failure predictor with exact per-feature Shapley values. The defining correctness invariant is asserted in CI:

CheckResult
sum(shap_values) + base_value == model raw marginexact (1.3735 ≈ output_margin 1.3736; tol 1e-3)
Top driver for a worn machineTool wear [min] (increases_risk) — physically correct
Attribution count == model feature count✓

Honest nuance (stated, not hidden): XGBoost applies a base_score offset, so sigmoid(margin) ≈ p_fail within ~0.02. The SHAP values are exact in margin space; the reported p_fail is the predictor's calibrated probability. Both are returned; the method note explains the relationship.

3. The real counterfactual

explain(...)["counterfactual"] is a guided minimal-change search over the actual predictor: how far must an actionable feature (tool-wear↓, torque↓, rpm↑) move to flip the machine from at-risk to safe — every candidate scored by the real model. Verified in CI: applying the returned minimal change genuinely drops p_fail below threshold. When no single-feature change suffices, it reports that honestly ("needs combined action") — no fabricated "fix". This is DiCE-style intent without the heavy dice-ml dependency.
