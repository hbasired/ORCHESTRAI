1. Why & what

CNSA 2.0 requires hybrid post-quantum crypto now and PQ-only for national-security surfaces by 2027. Stage 18 puts every external boundary on hybrid ML-KEM-768 + X25519 key exchange, signs long-trust artefacts (firmware / policy / model cards) with SLH-DSA-SHA2-128s, and makes the whole thing crypto-agile.

peer ──TLS 1.3, group X25519MLKEM768──> OpenSSL-3.5 sidecar (ML-DSA-65 cert) ──plain HTTP loopback──> agent firmware/policy/model-card ──SLH-DSA-SHA2-128s (FIPS 205)──> self-verifiable attestation

A real handshake, not a scaffold: the host's OpenSSL 3.5.4 has native ML-KEM/ML-DSA/SLH-DSA.

2. The build (all real)

  • ML-KEM-768 (FIPS 203) — backend/crypto/pqc_kem.py via kyber-py (pure-Python, the ML-KEM sibling of the Stage-13.5 dilithium-py signer); app-level KEM for when the sidecar is off-path.
  • SLH-DSA-SHA2-128s (FIPS 205) — backend/crypto/pqc_slh_dsa.py via the OpenSSL 3.5 CLI; all 7 model cards carry a self-verifiable SLH-DSA footer; sign-firmware-bundle.py signs bundles.
  • Hybrid TLS sidecar — docker-compose.pqc.yml fronts A2A/REST/WS/MQTT/OPC-UA; gen-pqc-tls-cert.sh emits the ML-DSA-65 cert chain.
  • 4-key-type rotation — rotate-pqc-keys.sh now drives a real key_manager CLI (identity/tls/firmware/hmac × --mode × --dry-run); each writes a key_rotation audit marker. (Fixed a real defect — the script referenced a CLI that never existed.)
  • Classical-crypto gate — audit.sh now fails on real RSA/EC API calls in backend/crypto+backend/a2a (matches code, not the forbidden-list comments).
