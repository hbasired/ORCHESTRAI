1. A learned injection-detection tier (G-077)

security/injection_classifier.py: a logistic-regression over bge-small embeddings, trained on the real Stage-20 corpus (153 attacks + 64 benign). It becomes the PRIMARY calibrated semantic decision inside prompt_guard.inspect() — replacing the raw kNN single-threshold (the kNN stays an honest fallback). An optional free-LLM judge (use_judge=True, Groq→Ollama) escalates the uncertain probability band and the no-keyword unsafe-intent case ("release the load over the walkway").

2. Continuous behavioural anomaly monitor (G-064-tail)

security/behavioral_monitor.py is the ONLINE counterpart of the Stage-25 nightly post-market sweep. It maintains a rolling robust-Z (median/MAD) baseline over the runtime's REAL per-incident behavioural features (decision count, tool calls, actuation attempts, verifier rejections, node revisits, duration) and adds explicit trajectory checks for the canonical agent anomalies — loops, redundant actions, invalid tool arguments, and actuation attempts exceeding decisions. It emits a signed behavior.anomaly row, reports insufficient_history below warmup (no fabricated baseline), and features_from_run() consumes a real run_incident result. Labelled eval: detection 1.0 / FPR 0.0.

4. Honesty notes (surfaced, not hidden)

  • Every injection number is held-out cross-validation — never train-on-test (the one thing a reviewer must check).
  • The learned tier REPLACES the kNN as the primary semantic decision (so FPR can drop), not just an extra OR-tier (which could only raise FPR).
  • Corpus-scale (217 examples); real-traffic + multilingual/obfuscated-attack validation needs a pilot (G-035).
  • No detector is fool-proof (OWASP) — the binding actuation gate stays safety/validator (Rule 3); these are defence-in-depth.
  • The behavioural monitor currently consumes run_incident output post-hoc; an always-on runtime hook is a small follow-up.
