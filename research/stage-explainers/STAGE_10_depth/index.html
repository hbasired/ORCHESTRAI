1. Why this deepening

The v0 Stage-10 explainer kept exact TreeSHAP (already exact) but offered only a single-feature greedy counterfactual, and deferred DiCE + global SHAP as "later refinements". Hard Rule 11a says the deeper version IS the first implementation — so the deferral is closed.

Diverse multi-feature recourse (DiCE) + dataset-level driver view (global SHAP).

2. DiCE diverse counterfactuals VERIFIED FLIPS

backend/ml/dice_explainer.py uses dice-ml to generate several DIFFERENT minimal recipes that each flip the predictor at-risk → safe. It varies only the actionable base physical features (torque↓, rpm↑, tool-wear↓) through a black-box wrapper of predict_failure, so the derived features (temp_diff, power_w) are recomputed internally — every counterfactual is physically consistent. Each recipe is re-verified against the REAL predictor. Measured on an at-risk machine (p_fail 0.966):

3. Global SHAP

global_importance(n) aggregates XGBoost's exact native TreeSHAP over a reference sample → mean |Shapley| per feature (dataset-level "what drives risk in general"), complementing the per-decision SHAP. Dependency-light. Measured top drivers: power_w, rotational speed, torque.

4. Honest scope & what changed

  • Methods over the existing XGBoost model — no new trained weight (no model card); still over an AI4I-proxy predictor (G-035).
  • Derived features kept consistent — DiCE varies base features only; an alternative that varied temp_diff/power_w directly would produce physically-inconsistent counterfactuals (rejected).
  • Multi-model neural Deep-SHAP scoped (not faked) — extending attribution to the RUL transformer / defect CNN is a documented future item with rationale (those are perception/forecast models; the predictor is the in-loop decision model whose recourse matters most). Nothing fabricated for the neural models.
