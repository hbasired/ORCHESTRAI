Stage 17 — Functional Safety Wrapper + Agentic Zero-Trust CLOSED

The LLM can plan, but it can never touch an actuator unchecked · ADR 2026-06-21_stage17_functional_safety_wrapper.md · KB_17 · research §27.

1. The core idea

LLM = planner. A classical SIL-rated controller = executor. A formal contract gates every actuator command. An LLM is non-deterministic, so it can never provide the validation IEC 61508 / ISO 13849 require — it proposes plans; a deterministic validator gates them; only the SIL bridge actuates.

plan ─> validator.validate(action, world_state, contract) ──blocked?──> fail-safe (STO / SS1 / operator_confirm) │ allow + SIL≥2 v sil_bridge.execute ──emits actuator.* span──> certified PLC (integration point) INVARIANT (CI): every actuator.* span MUST be preceded by a safety.validate.* span

No actuator path exists that bypasses the validator — and CI mechanically enforces it.

2. The safety wrapper (backend/safety/)

  • contract.py + contracts/ — the Pydantic safety-contract DSL + 5 named contracts (move_amr_to_charging_station, start_conveyor_segment, expedite_supplier_order [SIL 0], change_machine_state, dispatch_amr_to_zone) with real precondition/invariant/postcondition checks + ISO clauses + a fail-safe path.
  • validator.py — validate() gates preconditions + invariants then routes by SIL (≥2→sil_bridge, 1→operator_confirm, 0→direct). A failing OR raising check blocks (fail-safe) + signs an audit row.
  • sil_bridge.py — the ONLY emitter of actuator.* spans; refuses any non-allowing / mis-routed Decision (no bypass). Honest certified-PLC integration point (no SIL cert claimed).
  • sto_ss1.py (STO/SS1 + signed audit rows) · sil_pl_map.py (IEC 61508 SIL ↔ ISO 13849-1 PL; ISO 10218-1:2025 PL d/SIL 2 for Class II).

3. Self-healing (KB_17 extension)

Joint-torque anomaly (robust rolling-Z > 3σ) → a behaviour-tree self_diagnose_calibrate (AMR + manipulator YAML trees) → resume (the resume itself passes the validator — we never skip safety during self-repair) OR, on calibration failure, STO + quarantine. Every transition signs an audit_chain row.

4. Agentic zero-trust (CTO #3 G-063/G-064 — backend/security/)

Adopted NIST SP 800-207 (+ CSA Agentic Trust / MAESTRO / OWASP NHI), 5 pillars mapped:

  • Identity — a per-internal-agent ML-DSA-65 non-human identity (owner + purpose + capabilities); each agent signs statements as itself.
  • Application/Workload — MCP tool least-privilege capability authz + argument sanitisation (injection/oversize/depth) + rate-limiting + an ML-DSA-65 signed tool manifest that detects a rogue/injected tool.
  • Data — audit_chain hash-chain + ML-DSA-65 sigs; Mem0 namespace isolation. Network/Device — A2A pinned-roots LIVE; live ML-KEM mTLS + attestation = Stage 18.
