1. Why & what

Stage 11 wired the Stage-4-10 models into the LangGraph runtime as direct Python imports. Stage 11.5 exposes them — plus the simulation, the KPI math, and the decision ledger — as five MCP tool servers (the vendor-neutral agent↔tools standard), and mounts them into the runtime. This is the substrate the external A2A boundary (Stage 14) and the memory layer (Stage 12) build on.

3. The mount — a thin in-house bridge (a real engineering decision)

The canonical langchain-mcp-adapters requires langchain-core>=1.0 — a major migration off our frozen langchain-core 0.3.28 + langgraph 0.2.60 runtime (bumping it reintroduces the Reviver break resolved in Stage 11). So agents/runtime/mcp_mount.py::MCPToolMount uses the official mcp stdio client directly (the same mechanism the adapter uses for stdio) and wraps each tool as a langchain_core.tools.StructuredTool, building the args model from the tool's JSON inputSchema. Persistent sessions amortise the heavy-ML import. main.py mounts the suite when MCP_MOUNT=1. Pins: mcp==1.27.2, starlette==0.41.3 (cap for fastapi 0.115.6), pydantic→2.13.4. (research §18; langchain-mcp-adapters ledgered for the langchain-core-1.0 work, G-056.)

4. Three stdio-safety defects — found by running the REAL stdio path

The in-process smoke passed, but the real stdio servers hung. Diagnosed + fixed (Rule 11b: shallow work hides gaps):

  • Worker-thread import-lock deadlock. FastMCP runs a sync @tool in an anyio worker thread; a first-time heavy import (torch/xgboost/numpy/simulation) inside that thread deadlocks on the CPython import lock in a subprocess. Fix: warm the heavy imports at each server's module top-level (main thread).
  • Background-thread SimWorld. SimWorld.start() (its worker thread + realtime sleep) deadlocks in the stdio worker-thread context. Fix: advance SimPy synchronously (env.run(until=…)) — deterministic + fast (~0.9s for 1800 sim-s).
  • Minimal subprocess env. StdioServerParameters defaults to a stripped env; fix: pass the full parent env (+ single-threaded BLAS).
