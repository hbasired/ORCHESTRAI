Stage 13 — CDC Ingestion CLOSED

A DB write drives the agent · ADR 2026-06-15_stage13_cdc_ingestion.md · KB_05 §97 · research §22. Verified live against the real Docker Postgres.

1. Why & what

Until now, problems reached the agent via the REST inject endpoint or the chat path. Stage 13 closes the bidirectional loop: an external system (or an operator) can write the database — INSERT an incidents row, or flip a stages.status to a trouble value — and that change flows automatically into the live SimWorld as an injected event, which then runs through the full self-healing runtime + audit chain + traces.

DB write (INSERT incidents / UPDATE stages.status) └─ cdc_emit() trigger ─→ cdc_outbox row (durable, jsonb diff) + pg_notify('cdc_events') └─ cdc_listener (LISTEN + drain-on-connect) ─→ change_to_inject() ─→ SimWorld.inject() └─ Stage-11 runtime ─→ Stage-12 audit_chain ─→ Stage-12.5 traces

2. The mechanism — and why this one (research §22)

Transactional outbox + LISTEN/NOTIFY signal + drain-on-connect — the research-endorsed robust CDC for a single self-hosted Postgres. Every alternative failed a real constraint:

Debeziumreached end-of-life 2026-03-31

test_decodingresearch: "avoid in production" (no filtering/type-handling/reliable parsing)

wal2jsonnot in the pgvector image (needs a custom build)
transactional outbox + NOTIFY + drain ✓durable, ordered, transactional, low-latency, native, free, parseable — picked

3. Two engineering calls (honest)

  • Sync-psycopg background thread, not async. psycopg's async mode cannot use Windows' ProactorEventLoop — which the rest of the app needs for the MCP stdio subprocesses (verified InterfaceError). Changing the global loop policy would break that. The SimWorld's inject() is already thread-safe, so a daemon thread running sync LISTEN is the robust, portable choice.
  • Durable, not just signalled. LISTEN/NOTIFY alone loses events if the listener is offline. The outbox is the durable store; the listener drains on connect (and per-notify), ORDER BY id FOR UPDATE SKIP LOCKED — so a row written while the listener was down is caught at startup (tested). No SimWorld bound → the row is left unprocessed and retried, never marked done without injecting.

5. Honest residual

  • G-068 pgoutput-based WAL logical replication (for streaming changes to a non-PG sink / Kafka at scale) → Stage 15 / a scale stage. The outbox path is the right pattern for the in-process SimWorld-inject case today.
  • The stages.status→inject mapping (trouble statuses → machine_crack) is a sensible default; refine per pilot.
