1. Unforgeable actuation capability tokens (C6-R1 / G-075)

safety/capability_token.py: validate() mints an HMAC token on every ALLOW, bound to the canonical decision + a hash of the exact action + a nonce + issue time. sil_bridge.execute() now actuates ONLY via one of two forgery/TOCTOU-resistant paths:

(a) RE-VALIDATE   given contract + world_state → re-run validate() against CURRENT
                  state, ignore the passed verdict   (forgery + TOCTOU proof)
(b) TOKEN         the Decision must carry a VALID, FRESH token bound to THIS action

rejected: forged (no token) · stale (replay/TOCTOU) · wrong-action · tampered

Verified by 7 dedicated tests: the genuine round-trip and re-validate path actuate; a hand-forged Decision(allow=True), a token minted for a different action, a stale token, and a tampered token are all rejected. The full 26-test safety suite still passes. Defence-in-depth — the binding gate remains the validator.

2. Always-on runtime behavioural oversight (C6-R3)

The Stage-31 behavioural monitor was eval-only. Now run_incident feeds every live incident's real behavioural features (decision count, tool calls, actuation attempts, verifier rejections, node revisits) to the monitor when RUNTIME_BEHAVIOR_MONITOR=1 — robust-Z + trajectory checks on 100% of live runs, a signed behavior.anomaly row on deviation. Off by default, off the hot path, honest-degrading (a monitor error never fails the incident); runtime determinism holds with it off.
