1. What this stage built & why now

CTO Checkpoint #1's verdict was blunt: "spec-deep, code-thin — freeze new spec, build ONE end-to-end vertical slice (predict→diagnose→intervene on the machine-failure scenario) before widening." Stage 6 is that slice.

Before this stage, the project had two trained brains sitting passively (Stage 4's XGBoost failure predictor, PR-AUC 0.847; Stage 5's LSTM demand forecaster) and a deterministic SimPy plant. Nothing connected prediction to action. Stage 6 closes the loop for the first time: live simulator telemetry flows into the real failure brain, a deterministic diagnoser names the root cause with an evidence trail, and the coordinator executes a preventive intervention inside the simulation — measured against doing nothing.

This is also the fundability artifact (PRD v3 §19): the demo that converts "spec-deep" into "working closed loop" — the precondition every investor/pilot conversation was blocked on.

3. How the loop works (file by file)

1. SENSE
simulation/entities/stage.py — each machine derives AI4I-unit telemetry (temps, rpm, torque, tool wear) from REAL sim state: wear accumulates per unit produced; a cracking machine slows, overstrains, heats, and wears toward the AI4I failure regimes. Seeded sensor noise; deterministic per world seed.
2. PREDICT
ml/failure_predictor.py — the real Stage-4 XGBoost brain (PR-AUC 0.847, recall-tuned threshold 0.779) scores every sample. No brain ⇒ ModelUnavailableError — never a fabricated probability.
3. DIAGNOSE
services/diagnosis.py — deterministic root-cause v0: ranked hypotheses (wear breach / overstrain / heat dissipation / power anomaly / external power event / no-fault-found), each with an explicit evidence trail. Pure function; 9 unit tests.
4. DECIDE
services/intervention_policy.py + agents/embodied_agent.py::decide_intervention — one shared deterministic policy (maintain / wait-external / monitor) used by both the live coordinator and the A/B harness, so they cannot drift. External power events are NOT "fixed" with machine maintenance; weak uncorroborated model signals are monitored, not acted on.
5. INTERVENE
stage.start_maintenance() — sim-only planned maintenance: cancels the pending crack, resets wear, costs 0.5×MTTR (vs 2.5×MTTR for an unplanned crack breakdown). Every decision + rationale + evidence lands in the provenance trail.
6. OBSERVE
services/slice_runner.py + services/ws_broker.py — SliceLoop (in-sim, deterministic) and LiveSliceRunner (asyncio → Redis) share one loop body; slice events (prediction/diagnosis/intervention/ab_report) ride the canonical KB_04 envelope over /ws.

5. Honest limits & what v0 is NOT

  • The telemetry is simulator-generated by construction. The mapping (sim state → AI4I units) is physics-motivated and documented, but the brain was trained on CNC-machine proxy data (AI4I 2020) — real-plant re-fit remains gated on a pilot (G-035). The sim was NOT tuned to flatter the model; thresholds come from the dataset's published failure-mode definitions.
  • Diagnosis v0 is rules, not causal inference. The causal digital twin + counterfactuals arrive at Stage 8 (G-019/G-020); active probing (diagnose.request/report) at Stage 11 (G-026) — same interfaces, deeper brains.
  • Intervention v0 is one action (planned maintenance), sim-only. No real actuator exists, so the Stage-17 safety wrapper is not yet in the path — by design, and it must be before any non-sim actuation. PPO recovery selection is Stage 7 (G-025); repair-robot dispatch Stage 11/16 (G-005).
  • Throughput didn't improve at this calibration (arrival-limited plant) — the value is availability. A capacity-limited calibration would likely show throughput gains; not claimed until measured.
  • The demand forecaster is still not in the live path (G-036, Stage 11) — Stage 6 deliberately touched only the machine-failure scenario.

6. What the next stages start with

  • Stage 7 (RL intervene): replaces intervention_policy.decide_intervention with a PPO policy over the same decision contract — the A/B harness becomes its training/eval environment.
  • Stage 8 (world model + causal twin): replaces the rule ranking in diagnosis.py behind the same Diagnosis interface.
  • Stage 11 (production slice): durable LangGraph workflow + HITL + active diagnosis + repair dispatch wrap this loop (G-005/G-014/G-025/G-026); LiveSliceRunner is the seam.
  • Stage 12.5 (PdM dashboard, G-006): consumes the slice envelopes already flowing on /ws.
