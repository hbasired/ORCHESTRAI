# Dependency exceptions — load-bearing pins (G-065, Stage 18)

> Why `pip-audit` is **informative, not blocking** in CI, and what compensates. The attestable dependency set is the
> CycloneDX SBOM (`sbom.cyclonedx.json`, regenerated by the `sbom` CI job). `bandit` (SAST) **is** a blocking gate.

## The load-bearing pin set (deliberately frozen)

These pins are **load-bearing** — bumping any one in isolation breaks a working, verified integration. They are frozen
for reproducible, attestable, audit-grade builds (EU AI Act Annex IV needs a frozen set), and advanced only via the
quarterly **"bump + full live re-test"** drill (G-055 / G-056 / G-065), never ad-hoc.

| Pin | Why frozen | Bump path |
|---|---|---|
| `langgraph==0.2.60` ↔ `langgraph-checkpoint<3` ↔ `langgraph-checkpoint-postgres` | the durable-runtime trio is version-coupled; langgraph-core 1.0 is a breaking migration (G-055) | langchain-core-1.0 migration drill |
| `starlette==0.41.3` | capped for `fastapi<0.42` (mcp pulled starlette 1.3.1 → broke fastapi) | with the fastapi/mcp bump |
| `mcp==1.27.2` | needs langchain-core≥1.0 for `langchain-mcp-adapters` — off our frozen 0.3.28 (G-056) | langchain-core-1.0 migration |
| `protobuf>=4.25,<5.0` ↔ `grpcio-tools==1.62.3` | **TensorFlow 2.15** (dice-ml/Stage 10) requires `protobuf<5`; grpcio-tools 1.81 forces 6.x (research §25.4) | when TF is upgraded / dice-ml replaced |
| `httpx==0.27.2` | shared by fastapi/starlette/mcp/langfuse; bumping risks the same skew (a2a-sdk needs ≥0.28.1 — G-070) | dependency-refresh stage |

## Compensating controls (so this is risk-accepted, not ignored)

1. **`bandit` SAST is BLOCKING** — code-level vulnerabilities (shell=True, eval, weak crypto, etc.) fail CI.
2. **CycloneDX SBOM** (`sbom` CI job, blocking generation) — the exact frozen set is enumerable + attestable; a CVE
   that lands on a pinned component is visible in the SBOM-driven review even though pip-audit is non-blocking.
3. **`pip-audit` still runs** (informative) — its output is triaged against this file; an advisory on a **non-pinned**
   dep (i.e. not in the table above) is a real finding and is fixed promptly (it isn't load-bearing).
4. **The audit-baseline + classical-crypto gate** (`scripts/audit.sh`) block fake/forbidden-crypto regressions.
5. **Quarterly bump drill** — the frozen pins are advanced together with a full live re-test (the langchain-core-1.0
   migration is the first scheduled drill).
